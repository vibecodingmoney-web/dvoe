# Подробная инструкция: от папки с кодом до работающего приложения в Telegram

Рассчитана на первый проект. Идём строго по порядку. Всё бесплатно. Названия кнопок на сайтах иногда немного меняются, ориентируйтесь на смысл.

**Что понадобится:** компьютер (Windows или Mac), Telegram, почта. Аккаунты заведём по ходу: GitHub, Neon, Render, UptimeRobot.

**Итоговая схема:**
```
папка dvoe → GitHub (хранит код) → Render (запускает сервер) ← UptimeRobot (будит сервер)
                                        ↕
                                  Neon (база данных) ↔ Telegram (бот + Mini App)
```

---

## Часть 1. Код → GitHub

### 1.1. Распакуйте архив
Распакуйте `dvoe.zip`. Получится папка `dvoe`, внутри неё должны лежать `package.json`, `README.md`, папки `src`, `public`, `test`. Если вместо этого внутри ещё одна папка `dvoe`, значит рабочая та, что внутри (где лежит `package.json`).

### 1.2. Установите Git
Git — программа, которая отправляет код на GitHub.
- **Windows:** скачайте с git-scm.com/download/win, установите, везде нажимая *Next* (настройки по умолчанию подходят).
- **Mac:** откройте «Терминал» и введите `git --version`. Если Git не установлен, macOS сам предложит поставить инструменты разработчика, согласитесь.

Проверка: откройте терминал (на Windows это **Git Bash** из меню «Пуск») и введите:
```bash
git --version
```
Должна появиться версия, например `git version 2.45.0`.

### 1.3. Создайте аккаунт GitHub
1. Откройте github.com → **Sign up**, пройдите регистрацию и подтвердите почту.
2. Запомните свой **логин** (username), он понадобится ниже.

### 1.4. Создайте пустой репозиторий
Репозиторий — это «папка проекта» на GitHub.
1. На github.com нажмите **+** (справа вверху) → **New repository**.
2. **Repository name:** `dvoe`.
3. Выберите **Private** (закрытый: код увидите только вы). Render сможет его читать после того, как вы дадите разрешение.
4. **Ничего не отмечайте** в пунктах *Add a README*, *.gitignore*, *license*. Репозиторий должен остаться пустым.
5. Нажмите **Create repository**.
6. На открывшейся странице скопируйте адрес вида `https://github.com/ВАШ_ЛОГИН/dvoe.git`.

### 1.5. Представьтесь Git (один раз)
В терминале (подставьте свои имя и почту, ту же, что на GitHub):
```bash
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
```

### 1.6. Откройте терминал в папке проекта
- **Windows:** откройте папку `dvoe` в проводнике → правая кнопка мыши → **Open Git Bash here** (или «Показать дополнительные параметры» → Git Bash Here).
- **Mac:** в Терминале введите `cd ` (с пробелом), перетащите папку `dvoe` в окно терминала и нажмите Enter.

Проверка, что вы в нужной папке:
```bash
ls
```
В списке должны быть `package.json`, `src`, `public`. Если их нет, вы не в той папке.

### 1.7. Отправьте код на GitHub
Выполняйте команды по одной (адрес в `remote add` замените на свой из пункта 1.4):
```bash
git init -b main
git add .
git commit -m "Первая версия Двое"
git remote add origin https://github.com/ВАШ_ЛОГИН/dvoe.git
git push -u origin main
```
Что делает каждая: создаёт локальный репозиторий → отмечает все файлы → сохраняет «снимок» → привязывает адрес GitHub → отправляет.

**Вход в GitHub при `git push`.** Пароль от аккаунта GitHub вводить нельзя, он не принимается. Варианты:
- **Windows, самый частый случай:** откроется окно браузера «Sign in with your browser», войдите и разрешите. Дальше всё само.
- **Если спросили Username и Password:** Username — ваш логин, а вместо пароля вставьте **токен**. Как получить токен: GitHub → фото профиля → **Settings** → внизу слева **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)** → отметьте галочку **repo** → срок на ваше усмотрение → **Generate** → скопируйте токен (показывается один раз). При вводе токена в терминале символы не отображаются, это нормально, вставьте и нажмите Enter.
- **Самый простой вариант без команд:** программа **GitHub Desktop** (desktop.github.com): *File → Add local repository* → выберите папку `dvoe` → *Publish repository* (снимите галочку Keep this code private, если нужен открытый, или оставьте, если закрытый).

Если `git init -b main` выдаёт ошибку про `-b`, выполните `git init`, затем `git branch -M main`.

### 1.8. Проверьте результат
Обновите страницу репозитория на GitHub. Должны быть: папки `src`, `public`, `test`, файлы `package.json`, `README.md`, `render.yaml`, `.env.example`, `.gitignore`, `ИНСТРУКЦИЯ.md`. Файла `.env` быть **не должно**: там живут секреты, а он в `.gitignore`.

> **Запасной путь без Git:** на странице пустого репозитория нажмите *uploading an existing file*, перетащите **содержимое** папки `dvoe` (не саму zip-файл), дождитесь загрузки и нажмите **Commit changes**. Скрытые файлы (`.gitignore`, `.env.example`) браузер может не взять, на работу приложения это не влияет.

### 1.9. Как обновлять код потом
Изменили что-то в файлах → в терминале в папке проекта:
```bash
git add .
git commit -m "Что изменил"
git push
```
Render сам заметит изменения и перезапустит сервер (см. часть 4).

## Часть 2. Бот в Telegram

1. В Telegram найдите **@BotFather** (с синей галочкой) и нажмите *Start*.
2. Отправьте `/newbot`.
3. Введите **название** бота (любое, например «Двое»).
4. Введите **username**. Он должен заканчиваться на `bot`, например `dvoe_love_bot`. Если занят, придумайте другой.
5. BotFather пришлёт **токен** вида `123456789:AAH...`. Сохраните его в надёжном месте (заметки, менеджер паролей). Это `BOT_TOKEN`.
   - Токен нельзя выкладывать на GitHub, отправлять в чаты или показывать на скриншотах. Если он утёк: `/revoke` в BotFather и выпустить новый.
6. **Узнайте свой Telegram id** (нужен для админ-режима): напишите боту **@userinfobot**, он ответит числом `Id: 123456789`. Запишите это число.

## Часть 3. База данных (Neon)

Бесплатный Postgres на самом Render удаляется через 30 дней, поэтому база живёт на Neon.
1. Откройте neon.tech → **Sign up** (удобнее через GitHub).
2. **Create project**: имя `dvoe`, регион ближайший к вам (например *Europe / Frankfurt*). Запомните регион, на Render выберите такой же.
3. После создания откройте **Connect** (или Dashboard → *Connection string*). Скопируйте строку целиком, она выглядит так:
   ```
   postgresql://имя:пароль@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
   Если пароль скрыт звёздочками, нажмите *Show password* или кнопку копирования. Это `DATABASE_URL`.
4. Создавать таблицы не нужно: приложение сделает это само при первом запуске.

## Часть 4. Сервер (Render)

1. Откройте render.com → **Get Started** → войдите через **GitHub**.
2. **New +** → **Web Service** → *Build and deploy from a Git repository*.
3. Найдите репозиторий `dvoe`. Если его нет в списке, нажмите *Configure account* и разрешите Render доступ к этому репозиторию.
4. Заполните:

   | Поле | Значение |
   |---|---|
   | Name | `dvoe` (из него получится адрес `https://dvoe.onrender.com`; если имя занято, Render добавит цифры) |
   | Region | тот же, что у Neon (например Frankfurt) |
   | Branch | `main` |
   | Runtime / Language | Node |
   | Build Command | `npm install` |
   | Start Command | `npm start` |
   | Instance Type | **Free** |

5. Раздел **Environment Variables** → *Add Environment Variable*, добавьте по одной:

   | Key | Value |
   |---|---|
   | `BOT_TOKEN` | токен из части 2 |
   | `DATABASE_URL` | строка из части 3 (целиком) |
   | `ADMIN_IDS` | ваш Telegram id (число из п. 2.6). Несколько админов — через запятую |
   | `CRON_KEY` | любая длинная случайная строка, например `k9X2mQ7vLp4RtZ8wB3nY` |
   | `APP_TZ` | `Europe/Kyiv` |

6. Откройте **Advanced** и в поле **Health Check Path** впишите `/health`.
7. Нажмите **Create Web Service**. Откроется страница с логом. Сборка и запуск занимают 2–5 минут.
8. В логе должны появиться строки:
   ```
   🤖 Бот: @dvoe_love_bot
   🔗 Вебхук: https://dvoe.onrender.com/webhook
   🚀 Сервер слушает порт ...
   ```
   Это значит, что всё работает. Вверху страницы сервиса виден его адрес (`https://....onrender.com`). Откройте `ваш_адрес/health`: в ответ должно прийти `{"ok":true}`.

**Если в логе ошибка:**
- `Не заданы переменные окружения` → проверьте названия переменных (регистр важен) и значения.
- Ошибка подключения к базе → проверьте `DATABASE_URL`: строка целиком, с `?sslmode=require`, без пробелов и кавычек.
- Бот не стартует → проверьте токен.

После правки переменных: *Environment* → *Save* → Render перезапустит сервис сам.

## Часть 5. Чтобы сервер не засыпал (UptimeRobot)

Бесплатный сервис Render засыпает через 15 минут без запросов, а при пробуждении первый запрос идёт до минуты. Пока он спит, бот не отправляет уведомления.
1. Откройте uptimerobot.com → зарегистрируйтесь.
2. **Add New Monitor**:
   - Monitor Type: **HTTP(s)**
   - Friendly Name: `Dvoe`
   - URL: `https://ваш_адрес.onrender.com/health`
   - Monitoring Interval: **5 minutes**
3. **Create Monitor**. Через пару минут статус должен стать **Up**.
4. *Необязательно, но надёжнее:* добавьте второй монитор на `https://ваш_адрес.onrender.com/cron/tick?key=ВАШ_CRON_KEY`: он запускает рассылки извне.

## Часть 6. Проверка

1. В Telegram откройте своего бота → **Start**. Придёт приветствие с кнопкой **«Открыть «Двое» ❤️»**. Нажмите.
2. Введите имя, выберите пол и возраст, укажите дату начала отношений (и по желанию дату свадьбы) → **Создать наш мир**.
3. Нажмите **Отправить приглашение** и отправьте ссылку любимому человеку (или откройте её со второго аккаунта для теста).
4. Второй человек вводит имя, пол и возраст, нажимает «Присоединиться». У вас на экране появится «Вы теперь вдвоём».
5. Нажмите сердечко **«Думаю о тебе»**: партнёру придёт сообщение от бота. Следующее нажатие возможно через 3 часа.
6. Откройте **Календарь**, нажмите «Первый поцелуй» (шаблон), выберите дату → **Сохранить**.
7. Во вкладке **Питомец** выберите зверька, согрейте яйцо — оно вылупится. Дальше кормите и играйте вместе.

Приглашение работает через бота, дополнительные настройки в BotFather не нужны. (По желанию: `/newapp` в BotFather создаёт «прямую» ссылку на приложение; её адрес вписывается в переменную `MINIAPP_LINK`.)

## Часть 7. Админ-режим (только для вас)

Если ваш Telegram id указан в `ADMIN_IDS`, в приложении вверху справа появится кнопка **«⚙️ Админ-режим»**. У остальных пользователей её нет совсем, а сервер дополнительно проверяет ваш id при каждом запросе.
- **Админ-режим:** сводка (пары, пользователи, активность за 24 часа, число «Думаю о тебе» и ответов) и список **всех пар**: имена, id, статус «Вместе / Ждёт партнёра», сколько дней вместе, последняя активность, включены ли уведомления, код пары.
- **Обычный режим:** ваша личная пара, как у всех. Кнопка **«👤 Обычный режим»** возвращает обратно.
- Тексты ответов пар админу **не показываются**: это их личная переписка.
- Не помните свой id? Напишите боту `/id`.
- Чтобы добавить админа, допишите его id в `ADMIN_IDS` через запятую: `111111111,222222222`.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| Бот молчит на `/start` | Лог Render: есть ли строка `🔗 Вебхук`? Верный ли `BOT_TOKEN`? Не «спит» ли сервис (откройте `/health`)? |
| Приложение долго открывается | Сервис проснулся после сна. Проверьте, что монитор UptimeRobot в статусе Up |
| Партнёру не приходят сообщения | Он должен хотя бы раз нажать **Start** у бота (или нажать «Разрешить» в плашке внутри приложения) |
| Нет кнопки админ-режима | Проверьте `ADMIN_IDS` на Render (ваш id, цифры, без пробелов внутри) и что сервис перезапустился после правки |
| Хочу изменить фразы | Файл `src/content.js` (новые строки — в конец). Новые шаблоны дат — `public/templates.js`. Потом `git add .`, `git commit`, `git push` |
| `git push` просит пароль и не принимает | Нужен токен вместо пароля (п. 1.7) или GitHub Desktop |

Если что-то не получается, пришлите скриншот или текст ошибки (токен и строку базы закрасьте!) и скажите, на каком шаге остановились.
